Bot 避坑指南

跟 Skill 不同，bot 的坑大多不在「裝太多」，而在你把它請進了你的群組與對話。以下每一條都有實測或官方文件依據。

  1. 訊息會先經過作者伺服器，才到模型

    所有第三方 bot 都是「你 → bot 作者的伺服器 → 模型」。也就是說，你貼的截圖、文件、對話，作者那一端看得到。

    做法：個資、病歷、公司文件不要丟；先看它有沒有隱私政策與「清除歷史」入口，兩者都沒有就別用於工作群。

  2. 權限給太大，等於把伺服器交出去

    很多 bot 預設要 Administrator，實際只需要「發訊息＋管理訊息」。被盜帳號或被供應鏈攻擊時，權限就是你損失的上限。

    做法：用最小權限邀請；把它放在專用頻道；管理類 bot 只給管管群，不要全伺服器。

  3. 免費層幾乎都有上限，官方文案不會寫

    常見是每日 10–30 則就碰壁、或免費層偷偷換成小模型。第三方目錄的實測就抓到「同一題免費層回答的模型版本不同」。

    做法：進群前先用 /help 或置頂訊息確認上限；長期天天用，直接比價官方訂閱，別為了包裝付更貴。

  4. 「同名不同物」—— 認 handle，不要認名字

    EggBot、Alice、ChatGPT 這類名字在 Telegram／Discord 上各有幾十個同名變體，山寨版會抄名字與頭像。

    做法：只從官方網站或目錄的驗證標記進入；記 @handle 與 client ID，不記顯示名稱。

  5. 「人數」可以買，星數不會

    Discord 伺服器數與 Telegram 月活是自報或可刷的；GitHub 星數相對難刷，但也可以買。

    做法：三個指標交叉看，再看最後更新時間——半年沒動的，再紅也別裝。

  6. 清單型專案不等於可用的 bot

    GitHub 上大量 repo 叫 xxx-bot，但其實是框架、模板或被封存的舊專案（Discord 改過 API 與意圖權限，老 bot 直接失效）。

    做法：看 pushed_at 是否在近 60 天內、README 有沒有「已停止維護」、issue 有沒有回。

  7. 別把 token 貼進對話或放進公開 repo

    bot token 等於完整控制權。放到公開 repo 幾分鐘內就會被掃到（GitHub 有 secret scanning，但你自己先外洩就來不及）。

    做法：一律環境變數／secret；懷疑外洩就立刻在 BotFather／Developer Portal 重置。

  8. 交易、空投、代幣類 bot 先假設是詐騙

    這類 bot 的最終一步幾乎都是「連接錢包」或「授權轉帳」。一旦 approve，資產可被清空，而且無法撤回。

    做法：不連錢包、不簽名、不輸入助記詞；真的要用，用一次性小額錢包。

  9. 群組裡的 bot 也會被「提示注入」

    官方文件已明講：會讀外部內容的 AI，可能被藏在網頁／訊息裡的指令操縱（prompt injection）。群組 bot 讀誰都能貼的訊息，風險更高。

    做法：不要讓有工具權限的 bot 直接讀陌生人的訊息；重要操作留人工確認。

  10. 自架比訂閱安全，但要自己扛維護

    自架（例如 Egg Shen Bot 這類開源專案）資料留自己機器，但 token、依賴、API 變更都要你顧。

    做法：只自架仍在更新的專案；用獨立帳號與獨立機器；先在小群測試再上主群。
